## P0 — Blocks Ship (2 findings)

### F1. EncodeSBranch failure masked with `continue` in trampoline fixup loop
**File:** `comgr-hotswap-b0a0.cpp:320-343`  
**Reviewers:** CPP-1, CORR-1, LOGIC-1 (unanimous P0)  
**Confidence:** High

In `RetargetCodeObjectB0A0`, the deferred trampoline fixup loop uses `continue` when `EncodeSBranch` fails. This means:
- The trampoline body is appended to the ELF (via `GrowElfWithTrampolines`)
- But the forward branch at the original instruction site is **never written**
- The function still returns `AMD_COMGR_STATUS_SUCCESS`
- Callers receive a **semantically broken** code object with orphan trampolines

**Fix:** Treat any `EncodeSBranch` failure as fatal — abort the rewrite and return `AMD_COMGR_STATUS_ERROR`. Do not grow the ELF if fixup is incomplete.

### F2. EmitToNopSled mutates text before branch encoding succeeds
**File:** `comgr-hotswap-b0a0.cpp:154-176`  
**Reviewers:** LOGIC-2 (P1→elevated to P0 in synthesis due to interaction with F1)  
**Confidence:** High

`EmitReplacementCode` copies replacement bytes into the NOP sled **before** `EncodeSBranch` succeeds. If encoding fails, the sled bytes are overwritten but `write_pos` is not advanced. The text section is left in an **inconsistent** state (replacement bytes without branches), and later patches may overwrite the same sled region.

**Fix:** Encode both branches (or preflight the distance check) **before** any `memcpy`. On failure, either restore the sled from a snapshot or fill with `s_nop`.

## P1 — Should Fix (6 findings)

### F3. Unbounded ELF header walks in AdjustSectionHeaders / AdjustProgramHeaders
**File:** `comgr-hotswap-elf.cpp:243-306`  
**Reviewers:** CPP-4, CORR-4, CQ-16  
**Confidence:** High

`e_shoff`, `e_shnum`, `e_shentsize` (and program header equivalents) are read from the ELF header and used to compute `elf + e_shoff + i * e_shentsize` **without** verifying:
1. `e_shoff + (uint64_t)e_shnum * e_shentsize <= buffer_size`
2. No integer overflow on the product/sum
3. `e_shentsize >= sizeof(Shdr)`

Malicious or corrupt ELFs can cause **out-of-bounds read/write**.

**Fix:** Pass `size_t image_size` to both functions; validate all header fields with overflow-safe arithmetic before looping.

### F4. PatchElfIsa note parsing: OOB read and uint32 overflow
**File:** `comgr-hotswap-elf.cpp:366-409`  
**Reviewers:** CPP-2, CPP-3, CORR-5, CORR-8  
**Confidence:** High

Two issues:
1. `std::strncmp(owner, "AMDGPU", 6)` reads 6 bytes but `namesz` may be smaller — **OOB read**
2. `namesz_aligned = (namesz + 3) & ~3u` uses 32-bit arithmetic — large `namesz` values wrap, making `note_total` wrong and enabling further OOB access

**Fix:** Bound `strncmp` by `std::min(6u, namesz)`; widen alignment arithmetic to `uint64_t`; reject notes where `note_total > remaining_section_size`.

### F5. DecodeTextSection potential infinite loop on inst_size == 0
**File:** `comgr-hotswap-llvm.cpp:107-144`  
**Reviewers:** CORR-2, CQ-12  
**Confidence:** Medium

If `getInstruction` reports success with `inst_size == 0`, `pos` never advances and the loop never terminates. The AMDGPU disassembler may not do this in practice, but the API does not guarantee it.

**Fix:** After successful decode, require `inst_size >= 1`; otherwise treat as `Fail` and advance by 4.

### F6. ApplyByteReplace leaves 1-3 byte tail un-NOP'd
**File:** `comgr-hotswap-elf.cpp:155-174`  
**Reviewers:** CPP-5, CORR-3, CORR-9  
**Confidence:** High

NOP fill only runs while `remaining >= 4`. If `inst_size - replace_bytes.size()` leaves 1-3 bytes, those bytes retain the original instruction encoding — **invalid opcode mix**.

**Fix:** Either reject `inst_size % 4 != 0` (assert AMDGPU invariant) or explicitly handle sub-dword tail.

### F7. LLVMState::CE allocated but never used
**File:** `comgr-hotswap-internal.h:205`, `comgr-hotswap-llvm.cpp:81`  
**Reviewers:** SA-9, CQ-7  
**Confidence:** High

`llvm_state.CE` (MCCodeEmitter) is created in `InitLLVMImpl` but never read. `AssembleSingleInst` allocates a **fresh** emitter, backend, streamer, and parser per call, ignoring the cached one.

**Fix:** Either remove the unused member or refactor `AssembleSingleInst` to reuse `llvm_state.CE`.

### F8. Multiple segments can match in AdjustProgramHeaders
**File:** `comgr-hotswap-elf.cpp:296-304`  
**Reviewers:** CPP-6  
**Confidence:** Medium

The match condition `p_offset <= text_offset && p_offset + p_filesz >= text_end` can match **multiple** PT_LOAD segments in unusual layouts, adding `tramp_total` repeatedly and corrupting segment sizes.

**Fix:** Match only the tightest containing segment, or stop after first match.
